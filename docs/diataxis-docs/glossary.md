# Glossary

Each term is defined once, here. Other pages link to this list instead of
re-defining a term.

## Roles

### Extension user

A person who edits `launch.json`, `tasks.json`, `keybindings.json` or
`settings.json`. Does not edit this repository. Most readers of this
documentation are Extension users.

### Extension author

A person who edits this repository. The name comes from VS Code's own term
("Extension Authoring"). An Extension user may be a professional developer; the
difference is what a person edits, not their job title.

## Core concepts

### Command variable

A variable of the form `${command:commandID}`. When VS Code substitutes it, it
runs the command `commandID` and uses the command's result as the value.

### Input

An entry in the `inputs` block of a `launch.json` or `tasks.json` file, with
type `command`. The input's `command` field names the command to run; its
`args` field carries the command's arguments.

### Variable substitution

The step in which VS Code replaces `${...}` placeholders in a `launch.json`,
`tasks.json`, `keybindings.json` or `settings.json` value with computed text,
before the launch, task or keybinding runs.

### Workspace folder

One root directory of the opened workspace. A workspace with more than one
folder has several workspace folders, and many variables need to know which one
they refer to.

## This extension's concepts

### `remember` store

The in-memory place where this extension keeps values stored in one task so a
later task in the same session can use them. Cleared when the window reloads,
unless `commandvariable.remember.persistent.file` is set.

### POSIX form

A path written with `/` as the separator and a drive letter written as `/z/`
rather than `z:\`. Several commands produce paths in this form so one
configuration works on every operating system.

## VS Code concepts

### Extension Host

The part of VS Code that runs extension code. A desktop Extension Host runs in
Node; a web Extension Host runs in a browser sandbox. The desktop host offers
Node APIs such as file access; the web host does not.

### Entry point

The file VS Code loads to start an extension. This extension declares two:
`extension.js` for the desktop host and `out/extension-common.js` for the web
host.

### Activation event

A declaration in `package.json` that tells VS Code when to start the extension,
such as `onCommand:extension.commandvariable.dateTime`. The extension starts
when the named command is first used.

### Bundle

One generated JavaScript file containing the extension's code and the libraries
it uses, produced so the extension can run in a web Extension Host.

## Testing vocabulary

### Test double

A module that stands in for the real `vscode` module during unit tests and
records the calls made against it. See also **shim**.

### Shim

The generated package at `node_modules/vscode` that makes `require('vscode')`
resolve to the test double outside the Extension Host. It is regenerated by
the test scripts and never committed.
