# Repository layout

Every path in the repository, what it is for, and whether it ships in the published `.vsix`. The `.vscodeignore` file is the product boundary: an edit there changes what users install.

## Top-level files

| Path | Purpose | Ships |
| --- | --- | --- |
| `extension.js` | Desktop extension entry point (uses Node APIs) | yes |
| `extension-common.js` | Shared logic; bundled into the web entry point | no (bundled into `out/`) |
| `utils.js` | Pure helpers, no extension-host state | yes |
| `uuid.js` | Copied UUID library | yes |
| `yaml.js` | Copied `yaml` bundle (see [dependency and vendoring policy](../explanation/dependency-vendoring-policy.md)) | yes |
| `uuid-org.js` | Upstream copy of the UUID library. **Not used by the build.** | no |
| `out/extension-common.js` | Generated by rollup; declared as the `browser` entry point | yes |
| `package.json` | Manifest: commands, activation events, settings, entry points | yes |
| `README.md`, `CHANGELOG.md`, `CONTRIBUTING.md` | Reader-facing documents | no |
| `docs/diataxis-docs/` | This documentation tree | no |
| `.vscodeignore` | The list of paths excluded from the `.vsix` | no |
| `scripts/` | Maintenance tooling: bundle check, packaging, shim generation, docs checks | no |
| `rollup.config.js` | Build configuration for the web bundle | no |
| `eslint.config.mjs`, `vitest.config.mjs`, `.vscode-test.mjs` | Tool configurations | no |
| `test/` | Unit and integration tests | no |
| `coverage/` | Generated coverage reports | no |

## Test tree

| Path | Runs where | What lives there |
| --- | --- | --- |
| `test/unit/` | plain Node, `vscode` replaced by a test double | fast tests: logic, manifest contract, guardrails |
| `test/integration/` | real Extension Host | activation, command surface, end-to-end runs |
| `test/fixtures/workspace/` | loaded by the integration runner | the fixture workspace the integration tests open |
| `test/helpers/` | both | the `vscode` test double and fixture builders |

## What does and does not ship

Everything in the top-level directory other than `extension.js`, `utils.js`, `yaml.js`, `uuid.js` and `out/` is build or maintenance tooling and is excluded from the published `.vsix` by `.vscodeignore`. `out/` is deliberately not ignored: it is the web entry point declared by the `browser` field.
